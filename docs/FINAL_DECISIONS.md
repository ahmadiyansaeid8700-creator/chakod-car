# Chakod — Final Decisions

این فایل مرجع تصمیم‌های نهایی و تأییدشده برای آماده‌سازی لانچ چاکود است. موارد ثبت‌شده در این فایل تا زمانی که مالک پروژه صراحتاً درخواست تغییر ندهد، قفل محسوب می‌شوند و نباید در اصلاح صفحات دیگر ناخواسته بازطراحی شوند.

## اصل محصول — Mobile First

Status: APPROVED / LOCKED

- نسخه مرجع و اصلی چاکود موبایل است.
- ممیزی، طراحی و تأیید هر صفحه ابتدا باید در موبایل انجام شود.
- نسخه دسکتاپ باید از ساختار و تصمیم‌های نسخه موبایل تبعیت کند، نه برعکس.
- Bottom Navigation، رفتار لمس، اندازه Tap Targetها، خوانایی در عرض‌های کوچک، فضای امن پایین صفحه و جلوگیری از Overlay روی محتوا جزو معیارهای اصلی پذیرش هستند.
- هیچ صفحه‌ای فقط با تأیید دسکتاپ «نهایی» محسوب نمی‌شود؛ تأیید موبایل برای قفل نهایی الزامی است.
- تغییرات دسکتاپ نباید تجربه موبایل قفل‌شده را خراب کنند.

## اصل طراحی — تم چاکود و رابط مدرن

Status: APPROVED / LOCKED

- تمام صفحات جدید، بازطراحی‌ها و پنل‌های چاکود باید از هویت بصری یکپارچه چاکود پیروی کنند؛ صفحه عمومی و بی‌هویت با ظاهر پیش‌فرض Admin/UI قابل قبول نیست.
- بنفش چاکود و طیف‌های وابسته، هویت اصلی رابط هستند. سبز فقط برای وضعیت‌های مثبت، تأییدشده یا هویت معنایی کسب‌وکار استفاده شود و نباید جای هویت اصلی برند را بگیرد.
- طراحی باید مدرن، تمیز، دارای سلسله‌مراتب بصری واضح، عمق کنترل‌شده، کارت‌های مشخص، Radius و Shadow هماهنگ و فاصله‌گذاری منظم باشد.
- متن بسیار ریز ممنوع است. عنوان‌ها، Labelها، توضیحات، دکمه‌ها و اطلاعات کارت‌ها باید در موبایل بدون زوم خوانا باشند.
- هر صفحه باید در نگاه اول متعلق به چاکود به نظر برسد؛ استفاده صرف از یک رنگ بنفش روی رابط خنثی، «پیروی از تم چاکود» محسوب نمی‌شود.
- Design System صفحات تأییدشده باید تا جای ممکن در صفحات بعدی بازاستفاده شود و برای هر پنل یک زبان بصری مستقل و ناسازگار ساخته نشود.
- تغییرات ظاهری نباید منطق، دسترسی‌ها یا رفتار API را بدون نیاز محصول تغییر دهند.

## 2026-08-09 — بازار خودرو `/cars`

Status: APPROVED / LOCKED

### ساختار و هویت
- هدر بازار خودرو باید با هویت اصلی چاکود هماهنگ باشد: لوگوی رسمی، مسیرهای «خودروها»، «نمایشگاه‌ها»، «کسب‌وکارها»، نشان، وضعیت واقعی حساب کاربری و CTA ثبت آگهی.
- مسیر نمایشگاه‌ها در هدر `/dealerships` است.
- وضعیت حساب کاربری از کامپوننت مشترک `AuthStatus` استفاده می‌کند؛ دکمه ثابت و مستقل «حساب من» استفاده نشود.
- عرض اصلی هدر، Hero، تب‌های بازار و محتوای صفحه بر مبنای `1240px` تنظیم شده است.

### Hero و تب‌های بازار
- Hero بازار خودرو باید جمع‌وجور و روشن باشد؛ بنر بزرگ و سنگین بنفش استفاده نشود.
- Hero شامل عنوان، kicker فارسی و توضیح کوتاه است؛ کارت آماری جداگانه تعداد آگهی‌ها حذف شده است.
- عبارت‌های انگلیسی تزئینی مثل `CHAKOD CAR MARKET` در UI این صفحه استفاده نشوند.
- تب‌های «همه خودروها / لوکس / منطقه آزاد / اقتصادی» به شکل یک نوار واحد و فشرده نمایش داده شوند.

### Grid آگهی‌ها
- در دسکتاپ، فیلتر در یک ستون ثابت و آگهی‌ها در Grid سه‌ستونه نمایش داده می‌شوند.
- کارت‌های Grid بازار از کارت‌های Rail صفحه اصلی مستقل از نظر تراکم هستند؛ اصلاح Grid نباید Railهای صفحه اصلی را تغییر دهد.
- دایره بزرگ حرف اول برند از کارت Grid حذف شده است.
- کارت‌ها باید متراکم، خوانا و با تمرکز روی عنوان، موقعیت، فروشنده، مشخصات، قیمت و اقدامات اصلی باشند.
- Placeholder تصویر باید ساده باشد: نماد کوچک چاکود + عبارت «بدون تصویر». متن تبلیغاتی یا لوگوی بزرگ تکراری در Placeholder استفاده نشود.

### فیلتر
- ستون فیلتر دسکتاپ حدود `276px` و در سمت راست Grid قرار می‌گیرد.
- منطق فعلی فیلترها حفظ شود؛ تغییرات ظاهری نباید رفتار query params یا API را تغییر دهد.
- Inputها، Selectها و Labelها باید خوانا باشند و از متن بسیار ریز پرهیز شود.

### داده و API
- در نسخه تأییدشده Staging، آگهی‌های واقعی روی `/cars` بارگذاری می‌شوند و خطای «ارتباط با بازار خودرو برقرار نشد» مشاهده نمی‌شود.
- اتصال داده و منطق فیلتر در این مرحله سالم تلقی می‌شود؛ تغییر ظاهری بعدی نباید به API دست بزند مگر در صورت بروز خطای جدید قابل بازتولید.

### Staging
- یک timeout موقت روی `staging.chakod.com` مشاهده شد، اما بدون تغییر کد برطرف شد و سایت دوباره در دسترس قرار گرفت؛ بنابراین آن رخداد به عنوان ایراد قطعی کد `/cars` طبقه‌بندی نشد.

## 2026-08-09 — خودروهای لوکس `/cars/luxury`

Status: VISUAL APPROVED / DATA REVIEW REQUIRED

### ظاهر
- ساختار تأییدشده `/cars` در صفحه لوکس حفظ شده و تغییر مستقل در Header، Hero، تب‌ها، Grid یا Filter لازم نیست.
- تب «لوکس» به‌درستی Active است و عنوان/توضیح صفحه با Segment لوکس هماهنگ است.
- کارت‌های لوکس باید همان Design System قفل‌شده بازار خودرو را استفاده کنند؛ بازطراحی مستقل برای این صفحه انجام نشود.

### Blocker داده‌ای
- در Staging فعلی، پاسخ Segment لوکس شامل آگهی‌هایی مثل «دنا توربو» و «آریزو ۵» نیز هست؛ بنابراین صحت دسته‌بندی داده‌های لوکس هنوز تأیید نشده است.
- فرانت‌اند به‌درستی `segment=luxury` را به API می‌فرستد و نوع `CatalogSegment` نیز `luxury` را به‌صورت رسمی پشتیبانی می‌کند.
- تا زمانی که معیار رسمی لوکس در Backend/دیتابیس مشخص نشود، فرانت‌اند نباید با whitelist برند، قیمت یا تشخیص حدسی خودروها را حذف کند.
- قفل نهایی این صفحه منوط به تأیید منطق دسته‌بندی داده‌های Segment لوکس است.

## 2026-08-10 — Affiliate access

Status: APPROVED / LOCKED

- Affiliate یک `account_type` مستقل نیست؛ یک نقش/دسترسی اضافه روی حساب موجود کاربر است.
- فقط مدیر سایت/ادمین مجاز است Affiliate را برای یک حساب فعال یا غیرفعال کند.
- هیچ مسیر Self-service، دکمه «فعال‌سازی افیلیت»، ثبت‌نام مستقیم افیلیت یا ارتقای خودکار کاربر به Affiliate نباید در UI عمومی وجود داشته باشد.
- فرانت‌اند فقط وقتی Workspace یا کارت «همکاری و درآمد» را نمایش می‌دهد که Backend به‌صورت صریح و قابل اعتماد دسترسی Affiliate همان نشست/کاربر را تأیید کرده باشد.
- تا زمانی که Backend فیلد/Claim/Permission رسمی Affiliate را ارائه نکرده، فرانت‌اند نباید با نام فیلد حدسی مثل `is_affiliate` یا `affiliate_enabled` این دسترسی را شبیه‌سازی کند.
- دسترسی به داده‌های Affiliate، کمیسیون‌ها، درآمد و تسویه باید در Backend نیز اجباری و Role-based باشد؛ مخفی‌کردن UI به‌تنهایی کنترل دسترسی محسوب نمی‌شود.
