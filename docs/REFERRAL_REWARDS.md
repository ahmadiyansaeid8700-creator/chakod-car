# Chakod — Referral Rewards

Status: APPROVED PRODUCT DIRECTION / IMPLEMENTATION CONTRACT

این سند مدل ساده و عمومی «دعوت دوستان» چاکود را تعریف می‌کند. این مدل جایگزین مدل پیچیده Affiliate برای کاربران عادی است.

## مدل اصلی

- هر کاربر تأییدشده چاکود بعد از ایجاد حساب، یک کد دعوت/تخفیف اختصاصی و یکتا دارد.
- کاربر می‌تواند کد خود را برای دیگران ارسال کند.
- کاربر جدید هنگام ثبت‌نام یا اولین خرید واجد شرایط، کد معرف را وارد می‌کند.
- کاربر جدید مزیت/تخفیف خوش‌آمدگویی دریافت می‌کند.
- معرف فقط بعد از اولین خرید موفق و واجد شرایط کاربر جدید، پاداش دریافت می‌کند.
- پاداش معرف در نسخه اول به‌صورت اعتبار چاکود یا تخفیف خرید بعدی باشد؛ نه تسویه نقدی.
- مقدار پاداش‌ها، شرایط استفاده، سقف‌ها و فعال/غیرفعال بودن کمپین فقط توسط Backend/Admin تعیین می‌شود.

## چرا این مدل

- برای همه کاربران قابل فهم است.
- نیازی به درخواست Affiliate، تأیید ادمین، کمیسیون نقدی، شبا یا تسویه ندارد.
- عملیات مالی و ضدتقلب ساده‌تر می‌شود.
- Account V2 با یک کارت کوچک «دعوت دوستان» قابل پیاده‌سازی است.

## تعریف کاربر جدید

کاربر جدید باید حداقل شرایط زیر را داشته باشد:
- شماره موبایل تأییدشده و یکتا.
- قبلاً خرید واجد شرایط نداشته باشد.
- قبلاً پاداش معرفی اولیه برای همان هویت دریافت نکرده باشد.

تعریف دقیق eligibility منبع حقیقت Backend است و فرانت‌اند نباید آن را حدس بزند.

## جریان کار

1. کاربر A حساب چاکود دارد و کد اختصاصی خود را می‌بیند.
2. کد را برای کاربر B می‌فرستد.
3. کاربر B که واقعاً کاربر جدید است، کد را ثبت می‌کند.
4. مزیت خوش‌آمدگویی B روی خرید واجد شرایط اعمال می‌شود.
5. B پرداخت موفق انجام می‌دهد.
6. Backend خرید را به A منتسب می‌کند.
7. پاداش A ایجاد می‌شود.
8. در صورت لغو/بازپرداخت خرید، پاداش A نیز باید باطل یا برگشت داده شود.

## Account V2

برای همه کاربران یک بخش کم‌حجم با عنوان «دعوت دوستان» نمایش داده شود.

محتوا:
- کد دعوت من
- دکمه کپی/اشتراک‌گذاری
- متن کوتاه: «دوستت تخفیف می‌گیرد، تو هم بعد از اولین خرید موفق او پاداش می‌گیری.»
- تعداد دعوت‌های موفق
- پاداش‌های دریافت‌شده/قابل استفاده

این بخش نباید صفحه اصلی حساب را شلوغ کند و نباید به داشبورد بازاریابی پیچیده تبدیل شود.

## پاداش نسخه اول

پیشنهاد محصول برای ساده ماندن نسخه اول:
- کاربر جدید: تخفیف روی اولین خرید واجد شرایط.
- معرف: اعتبار چاکود یا کد تخفیف برای خرید بعدی، پس از موفق‌شدن اولین خرید کاربر جدید.
- پرداخت نقدی و تسویه بانکی در این مدل وجود ندارد.

نوع و مقدار دقیق reward باید Admin-configurable باشد و در Client Hardcode نشود.

## Attribution

- هر کاربر جدید فقط یک معرف اولیه معتبر داشته باشد.
- کد معرف باید قبل از نهایی‌شدن اولین خرید واجد شرایط ثبت شود.
- هر خرید واجد شرایط فقط یک Referral Reward ایجاد کند.
- ثبت کد به‌تنهایی برای معرف پاداش ایجاد نمی‌کند؛ خرید موفق شرط لازم است.
- اگر کد نامعتبر/غیرفعال باشد، پاداش ایجاد نشود.

## ضدتقلب

Backend باید حداقل این قواعد را enforce کند:
- Self-referral ممنوع.
- یک شماره موبایل/هویت نتواند چند بار پاداش «کاربر جدید» بگیرد.
- یک سفارش/پرداخت نتواند دوبار Reward ایجاد کند.
- Refund/Cancel باید Reward را معکوس کند.
- مبلغ تخفیف، پاداش و eligibility از Client قابل اعتماد نیست.
- در صورت نیاز، سقف روزانه/ماهانه دعوت یا پاداش توسط Admin قابل تنظیم باشد.

## Admin

ادمین باید بتواند:
- کمپین دعوت دوستان را فعال/غیرفعال کند.
- مقدار/نوع پاداش معرف را تعیین کند.
- مقدار/نوع تخفیف کاربر جدید را تعیین کند.
- شروط خرید واجد شرایط، حداقل مبلغ و تاریخ اعتبار را تنظیم کند.
- کد کاربر را در موارد خاص غیرفعال کند.
- آمار کل دعوت، خرید موفق و هزینه پاداش را ببیند.

## داده/API مورد نیاز

حداقل مفاهیم Backend:
- `referral_code` یکتا برای هر User
- `referrer_user_id`
- `referred_user_id`
- `referral_status`
- `qualifying_order_id/payment_id`
- `new_user_reward`
- `referrer_reward`
- `reward_status`: pending / granted / reversed / expired
- timestamps و Audit metadata لازم

## خارج از محدوده نسخه اول

- Affiliate اختصاصی با درخواست و تأیید مدیر
- کمیسیون درصدی از فروش
- تسویه نقدی/شبا
- MLM / زیرمجموعه چندسطحی
- کمیسیون بابت کلیک یا بازدید
- داشبورد بازاریابی پیچیده

اگر بعداً برنامه Affiliate حرفه‌ای لازم شد، باید به‌عنوان قابلیت جدا از Referral عمومی طراحی شود و نباید با این سیستم یکی گرفته شود.
